# Software Requirements Specification (SRS)
## ระบบเช็คและตรวจการบ้านออนไลน์ (Homework Tracking & Grading System)

---

### 1. ปัญหาและที่มา (Problem Statement & Stakeholder Needs)

#### 1.1 Problem Statement
ในกระบวนการจัดการเรียนการสอนแบบเดิม การสั่งและส่งการบ้านผ่านกระดาษ หรือผ่านช่องทางแชทกลุ่ม (เช่น LINE, Facebook Messenger, หรือ Email) ก่อให้เกิดปัญหาสำคัญดังนี้:
1. **งานสูญหายและข้อความตกหล่น:** ลิงก์หรือไฟล์ที่ส่งในแชทกลุ่มหมดอายุ ค้นหาย้อนหลังยาก และไม่มีจุดรวมไฟล์ที่เป็นระเบียบ
2. **ภาระงานของครูผู้สอนสูงเกินจำเป็น:** ครูต้องเสียเวลา 30–40% ในการไล่เช็คชื่อ บันทึกคะแนนลง Excel ด้วยตนเอง และทวงการบ้านรายบุคคล
3. **นักเรียนขาดการติดตามอย่างมีประสิทธิภาพ:** นักเรียนจำกำหนดส่งไม่ได้ ไม่ทราบสถานะว่างานของตนถูกส่งสำเร็จหรือยัง และไม่ได้รับคำแนะนำ (Feedback) รายบุคคลอย่างทันท่วงที
4. **ขาดความโปร่งใสและการเก็บหลักฐาน:** ไม่มีบันทึกเวลาส่งงาน (Timestamp) ที่ชัดเจน ทำให้เกิดข้อโต้แย้งเรื่องการส่งงานช้าหรือการส่งงานไม่ตรงเวลา

#### 1.2 Stakeholder Analysis
| กลุ่มผู้ใช้ (Stakeholder) | บทบาทในระบบ (Role) | ความต้องการหลัก (Needs) |
|---|---|---|
| **ครูผู้สอน (Teacher)** | ผู้จัดการรายวิชาและตรวจงาน | - สร้างการบ้าน กำหนด Deadline และแนบโจทย์<br>- ตรวจงานพร้อมดูพรีวิวไฟล์ ให้คะแนน และ Feedback ได้สะดวกรวดเร็ว<br>- ดูภาพรวมว่าใครส่งแล้ว ใครยังไม่ส่ง และ Export คะแนนเข้าสมุดบันทึกคะแนน |
| **นักเรียน (Student)** | ผู้รับมอบหมายและส่งงาน | - ดูตารางการบ้านและแจ้งเตือนวันกำหนดส่ง<br>- อัปโหลดไฟล์งานส่งได้อย่างสะดวกผ่านโทรศัพท์มือถือ<br>- รับคะแนนและ Feedback เพื่อนำไปปรับปรุงตนเอง |
| **ผู้ดูแลระบบ (Admin)** | ผู้ดูแลระบบและข้อมูลพื้นฐาน | - จัดการบัญชีผู้ใช้ จัดการห้องเรียน และดูแลความปลอดภัยของระบบ |

### 2. ขอบเขตของระบบ (System Scope)

#### 2.1 In-Scope (ระบบในระยะที่ 1 / MVP)
- **ระบบยืนยันตัวตนและจัดการสิทธิ์ (Authentication & RBAC):** รองรับบทบาทครู (Teacher), นักเรียน (Student), และผู้ดูแลระบบ (Admin)
- **ระบบจัดการห้องเรียนและรายวิชา (Classroom Management):** สร้างห้องเรียน เข้าร่วมห้องเรียนด้วยรหัสเชิญ (Class Code)
- **ระบบจัดการการบ้าน (Assignment Management):** สร้าง แก้ไข ลบ กำหนด Deadline, Max Score, คำแนะนำ และไฟล์ตัวอย่าง
- **ระบบส่งงาน (Submission Portal):** นักเรียนอัปโหลดไฟล์ (PDF, PNG, JPG, Word) หรือแนบข้อความ พร้อมระบบบันทึกเวลาส่งที่เที่ยงตรง
- **ระบบจัดการการส่งช้า (Late Submission Handling):** ตรวจจับการส่งหลัง Deadline และบันทึกสถานะ "ส่งช้า (Late)"
- **ระบบตรวจและให้คะแนน (Grading & Feedback):** ครูดูตัวอย่างไฟล์ (File Preview) ให้คะแนน และคอมเมนต์ข้อความกลับ
- **ระบบติดตามสถานะ (Tracking Dashboard):** จำแนกสถานะชัดเจน: *ยังไม่ส่ง (Missing/Pending)*, *ส่งแล้ว (Submitted)*, *ส่งช้า (Late)*, *ตรวจแล้ว (Graded)*
- **ระบบส่งออกข้อมูล (Export Reports):** ดาวน์โหลดคะแนนการบ้านทั้งห้องออกมาเป็นไฟล์ Excel/CSV

#### 2.2 Out-of-Scope (อยู่นอกขอบเขตระยะแรก)
- ระบบสอบออนไลน์แบบจับเวลาเรียลไทม์ (Live Examination / Proctoring)
- ระบบตัดเกรดอัตโนมัติทั้งหลักสูตร (Academic Transcript & GPA Calculation)
- ระบบตรวจจับการคัดลอกด้วย AI เชิงลึก (Advanced Plagiarism Detection)
- ระบบแชทสด หรือ Video Conference ในตัวระบบ

### 3. ข้อกำหนดเชิงฟังก์ชัน (Functional Requirements - FR)

#### หมวดที่ 1: การจัดการผู้ใช้และสิทธิ์ (Authentication & Profile)
- **FR-AUTH-01:** ระบบต้องรองรับการสมัครสมาชิกและเข้าสู่ระบบด้วย Email/Password พร้อมการยืนยันตัวตน
- **FR-AUTH-02:** ระบบต้องแยกสิทธิ์การใช้งาน (Role-Based Access Control) ระหว่าง Teacher, Student และ Admin อย่างเข้มงวด

#### หมวดที่ 2: การจัดการห้องเรียน (Classroom Management)
- **FR-CLS-01:** ครูสามารถสร้างห้องเรียน (Classroom) โดยระบบจะสร้างรหัสเข้าร่วมห้องเรียน (Class Code) อัตโนมัติ
- **FR-CLS-02:** นักเรียนสามารถเข้าร่วมห้องเรียนได้โดยการกรอกรหัส Class Code ที่ได้รับจากครู

#### หมวดที่ 3: การมอบหมายการบ้าน (Assignment Management)
- **FR-ASN-01:** ครูสามารถสร้างการบ้าน โดยระบุ: หัวข้อ, รายละเอียด, กำหนดส่ง (Deadline วันที่และเวลา), คะแนนเต็ม (Max Score) และไฟล์โจทย์แนบ
- **FR-ASN-02:** ครูสามารถตั้งค่าเปิด/ปิดการอนุญาตส่งงานล่าช้า (Allow Late Submission)
- **FR-ASN-03:** ครูสามารถแก้ไขหรือลบการบ้านได้ โดยหากมีการส่งงานเข้ามาแล้ว ระบบต้องแจ้งเตือนยืนยันก่อนลบ

#### หมวดที่ 4: การส่งการบ้านของนักเรียน (Submission Management)
- **FR-SUB-01:** นักเรียนสามารถอัปโหลดไฟล์การบ้าน (รองรับ PDF, JPG, PNG, DOCX) ขนาดไม่เกิน 25 MB ต่อไฟล์ หรือพิมพ์ข้อความส่ง
- **FR-SUB-02:** ระบบต้องบันทึกเวลาที่ส่ง (Submission Timestamp) ตามเวลาสากลของ Server
- **FR-SUB-03:** หากนักเรียนส่งงานก่อน Deadline ระบบต้องกำหนดสถานะเป็น `Submitted`
- **FR-SUB-04:** หากนักเรียนส่งงานหลัง Deadline (และครูอนุญาตส่งช้า) ระบบต้องกำหนดสถานะเป็น `Late` พร้อมระบุระยะเวลาที่ช้าไป
- **FR-SUB-05:** นักเรียนสามารถยกเลิกและส่งงานใหม่ (Resubmit) ได้ตราบใดที่ยังไม่พ้นกำหนดส่ง หรือยังไม่ได้รับการตรวจให้คะแนน

#### หมวดที่ 5: การตรวจและให้คะแนน (Grading & Feedback)
- **FR-GRD-01:** ครูสามารถเปิดดูไฟล์การบ้านของนักเรียนได้โดยตรงผ่านระบบ (In-browser Preview) โดยไม่ต้องดาวน์โหลดไฟล์ลงเครื่องทุกครั้ง
- **FR-GRD-02:** ครูสามารถกรอกคะแนน (ต้องไม่เกินคะแนนเต็มที่ตั้งไว้) และเขียน Feedback ข้อเสนอแนะแก่นักเรียน
- **FR-GRD-03:** เมื่อครูกดบันทึกผลการตรวจ ระบบต้องเปลี่ยนสถานะของงานเป็น `Graded` และส่ง Notification แจ้งเตือนไปยังนักเรียน

#### หมวดที่ 6: การรายงานผลและติดตาม (Dashboard & Reporting)
- **FR-REP-01:** ระบบต้องแสดง Dashboard สำหรับครู สรุปยอด: จำนวนนักเรียนทั้งหมด, ส่งตรงเวลา, ส่งช้า, ยังไม่ส่ง, และตรวจแล้ว
- **FR-REP-02:** ครูสามารถ Export สรุปคะแนนการบ้านของนักเรียนทุกคนในห้องเรียนออกมาเป็นไฟล์ CSV หรือ Microsoft Excel (.xlsx) ได้

### 4. ข้อกำหนดที่ไม่ใช่เชิงฟังก์ชัน (Non-Functional Requirements - NFR)

| รหัส | มิติคุณภาพ (ISO 25010) | รายละเอียดข้อกำหนด (Specification) | เกณฑ์การวัดผล (Metric / Verification) |
|---|---|---|---|
| **NFR-PERF-01** | Performance & Scalability | ระบบต้องรองรับโหลดช่วง高峰 (Peak Load) ก่อนเวลา Deadline อย่างน้อย 500 requests/sec | Response time ของหน้าเว็บเฉลี่ยไม่เกิน 2.0 วินาที |
| **NFR-PERF-02** | Upload Efficiency | กระบวนการอัปโหลดไฟล์ขนาด 25 MB ต้องมี Progress Bar แสดงความคืบหน้า | มี Feedback แสดง % การอัปโหลด และรองรับการ Re-upload หากเน็ตหลุด |
| **NFR-SEC-01** | Privacy & Access Control | นักเรียนต้องมองเห็นเฉพาะไฟล์งานและคะแนนของตนเองเท่านั้น ไม่สามารถเข้าถึงงานของผู้อื่นได้ | ตรวจสอบด้วย IDOR testing และ Object-level authorization checks |
| **NFR-SEC-02** | File Security | ระบบต้องตรวจสอบ MIME Type แท้จริงของไฟล์ และป้องกันการอัปโหลดไฟล์ที่อาจเป็นอันตราย (เช่น .exe, .sh, .bat) | Whitelist เฉพาะ MIME type ที่กำหนด และสแกนไวรัส/มัลแวร์ใน Bucket จัดเก็บ |
| **NFR-SEC-03** | Data Encryption | การรับส่งข้อมูลทั้งหมดต้องผ่าน HTTPS (TLS 1.3) และรหัสผ่านต้องถูกเข้ารหัสด้วย Argon2 หรือ bcrypt | ผ่านการตรวจสอบ SSL Labs Grade A+ และไม่มี plain-text password ในฐานข้อมูล |
| **NFR-REL-01** | Reliability & Availability | ระบบต้องมีความพร้อมใช้งาน (Availability) ไม่น้อยกว่า 99.5% ในช่วงเวลาทำการเรียนการสอน (07:00 - 22:00) | Uptime monitoring พร้อมระบบ Failover และการแจ้งเตือน Incident |
| **NFR-USA-01** | Usability & Accessibility | หน้าจอของนักเรียนต้องเป็น Mobile-First Responsive 100% ใช้งานผ่านสมาร์ตโฟนได้ราบรื่น | ผ่านเกณฑ์ Google Mobile-Friendly และรองรับความกว้างหน้าจอตั้งแต่ 360px ขึ้นไป |
| **NFR-AUD-01** | Auditability | ทุกธุรกรรมการส่งงาน การแก้ไขคะแนน และการตรวจงาน ต้องเก็บบันทึกประวัติ (Audit Log) ย้อนหลัง | มี Log บันทึก `user_id`, `action`, `timestamp`, `ip_address` อย่างน้อย 1 ภาคการศึกษา |

### 5. User Stories และ Acceptance Criteria

#### US-01: การสร้างการบ้านโดยครูผู้สอน
- **User Story:** ในฐานะ **ครูผู้สอน**, ฉันต้องการ **สร้างการบ้านพร้อมกำหนด Deadline และเกณฑ์คะแนน**, เพื่อให้ **นักเรียนในห้องเรียนทราบภาระงานและส่งงานได้ตรงเวลา**
- **Acceptance Criteria (Gherkin Syntax):**
  - **Scenario 1: สร้างการบ้านสำเร็จ**
    - **Given:** ครูได้เข้าสู่ระบบและอยู่ในหน้าห้องเรียนที่ตนเองเป็นเจ้าของ
    - **When:** กรอกชื่อการบ้าน "แบบฝึกหัดที่ 1", รายละเอียด, กำหนดส่งเป็นวันที่ในอนาคต, คะแนนเต็ม 10 คะแนน, และแนบไฟล์โจทย์ .pdf
    - **Then:** ระบบบันทึกการบ้านสำเร็จ และแสดงในการบ้านของห้องเรียน พร้อมแจ้งเตือนไปยังนักเรียนทุกคนในห้อง
  - **Scenario 2: กำหนด Deadline ย้อนหลัง**
    - **Given:** ครูอยู่ในหน้าสร้างการบ้าน
    - **When:** กรอกวันกำหนดส่งเป็นวันหรือเวลาในอดีต
    - **Then:** ระบบต้องแจ้งเตือนข้อผิดพลาด "วันกำหนดส่งต้องเป็นวันและเวลาในอนาคตเท่านั้น" และไม่อนุญาตให้บันทึก

#### US-02: การส่งการบ้านของนักเรียนตรงเวลา
- **User Story:** ในฐานะ **นักเรียน**, ฉันต้องการ **อัปโหลดไฟล์การบ้านส่งเข้าระบบก่อนถึงกำหนดส่ง**, เพื่อ **ส่งงานให้ครูตรวจและบันทึกคะแนน**
- **Acceptance Criteria:**
  - **Scenario 1: ส่งงานตรงเวลาสำเร็จ**
    - **Given:** นักเรียนอยู่ในห้องเรียน และมีการบ้านสถานะ "Pending" ที่ยังไม่ถึง Deadline
    - **When:** แนบไฟล์ `homework_v1.pdf` ขนาด 5 MB และกดยืนยัน "ส่งการบ้าน"
    - **Then:** ระบบบันทึกไฟล์และ Timestamp, เปลี่ยนสถานะเป็น `Submitted`, และแสดงข้อความยืนยันการส่งสำเร็จ
  - **Scenario 2: ส่งไฟล์ขนาดเกินที่กำหนด**
    - **Given:** นักเรียนเลือกส่งไฟล์ขนาด 30 MB (เกินขีดจำกัด 25 MB)
    - **When:** พยายามอัปโหลดไฟล์
    - **Then:** ระบบปฏิเสธการอัปโหลดทันทีที่ Client-side พร้อมแสดงข้อความเตือน "ขนาดไฟล์ต้องไม่เกิน 25 MB"

#### US-03: การส่งการบ้านหลังกำหนด (Late Submission)
- **User Story:** ในฐานะ **นักเรียนที่ส่งงานไม่ทันกำหนด**, ฉันต้องการ **ส่งงานหลัง Deadline ได้ (หากครูอนุญาต)**, เพื่อให้ **ยังได้รับคะแนนแม้จะถูกหักคะแนนส่งช้า**
- **Acceptance Criteria:**
  - **Scenario 1: ส่งงานล่าช้าเมื่อครูเปิดรับงานช้า**
    - **Given:** การบ้านเลยกำหนดส่งมาแล้ว 2 ชั่วโมง และครูเปิดการตั้งค่า "Allow Late Submission"
    - **When:** นักเรียนอัปโหลดไฟล์และกดยืนยันส่งงาน
    - **Then:** ระบบบันทึกงานโดยตั้งสถานะเป็น `Late (ส่งช้า 2 ชั่วโมง)` และแสดงป้ายกำกับสีส้มชัดเจนในหน้ารายชื่อของครู
  - **Scenario 2: พยายามส่งงานเมื่อครูปิดรับงานช้า**
    - **Given:** การบ้านเลยกำหนดส่ง และครูปิดการตั้งค่า "Allow Late Submission"
    - **When:** นักเรียนเปิดหน้าการบ้าน
    - **Then:** ปุ่มส่งงานถูกปิดการใช้งาน (Disabled) และแสดงสถานะเป็น `Missing (หมดเวลาส่ง)`

#### US-04: ครูตรวจงานและให้คะแนน
- **User Story:** ในฐานะ **ครูผู้สอน**, ฉันต้องการ **เปิดดูไฟล์การบ้าน ให้คะแนน และพิมพ์ข้อเสนอแนะ**, เพื่อ **ประเมินผลงานและช่วยให้นักเรียนพัฒนาการเรียนรู้**
- **Acceptance Criteria:**
  - **Scenario 1: ตรวจและให้คะแนนสำเร็จ**
    - **Given:** ครูเปิดดูรายการงานของนักเรียนที่มีสถานะ `Submitted`
    - **When:** ครูเปิดพรีวิวไฟล์ กรอกคะแนน `8.5/10` และพิมพ์ข้อความ "ทำได้ดีมาก อธิบายข้อ 2 เพิ่มเติมอีกนิดจะสมบูรณ์" แล้วกดยืนยัน
    - **Then:** ระบบบันทึกคะแนนและคำแนะนำ, เปลี่ยนสถานะงานเป็น `Graded`, และส่ง Notification แจ้งนักเรียนทันที
  - **Scenario 2: กรอกคะแนนเกินคะแนนเต็ม**
    - **Given:** การบ้านมีคะแนนเต็ม 10 คะแนน
    - **When:** ครูกรอกคะแนน `12`
    - **Then:** ระบบแสดงข้อผิดพลาด "คะแนนต้องอยู่ระหว่าง 0 ถึง 10 คะแนน" และไม่อนุญาตให้บันทึก

#### US-05: การ Export คะแนนเป็น Excel
- **User Story:** ในฐานะ **ครูผู้สอน**, ฉันต้องการ **ดาวน์โหลดตารางคะแนนรวมของทั้งห้องเรียนเป็นไฟล์ Excel/CSV**, เพื่อ **นำไปใช้ตัดเกรดหรือนำเข้าสู่ระบบทะเบียนโรงเรียน**
- **Acceptance Criteria:**
  - **Scenario 1: Export คะแนนสำเร็จ**
    - **Given:** ครูอยู่ในหน้ารายงานผลคะแนนของห้องเรียนที่มีนักเรียน 40 คน
    - **When:** กดปุ่ม "Export to Excel"
    - **Then:** ระบบสร้างไฟล์ `.xlsx` ที่มีคอลัมน์: รหัสนักเรียน, ชื่อ-นามสกุล, คะแนนการบ้านแต่ละชิ้น, สถานะการส่ง, และคะแนนรวม ได้ถูกต้องครบถ้วน

### 6. กฎทางธุรกิจ (Business Rules - BR)

1. **BR-TIME-01 (Timestamp Authority):**  
   เวลาที่ใช้ตัดสินว่าส่งตรงเวลาหรือส่งช้า ต้องใช้เวลาของ Server (UTC/Bangkok Time NTP Synchronized) เท่านั้น ห้ามยึดตามเวลาของเครื่อง Client นักเรียนเด็ดขาด
2. **BR-SUB-01 (Submission Lock After Graded):**  
   เมื่อการบ้านได้รับการตรวจและให้คะแนนแล้ว (สถานะ `Graded`) นักเรียนจะไม่สามารถกดส่งใหม่ (Resubmit) ได้ เว้นแต่ครูจะกดเลือกคำสั่ง "Request Revision / ให้ส่งแก้ไขใหม่"
3. **BR-FILE-01 (Storage Limit per Assignment):**  
   นักเรียน 1 คนสามารถแนบไฟล์ได้สูงสุด 3 ไฟล์ต่อการบ้าน 1 ชิ้น และขนาดรวมทั้งหมดต้องไม่เกิน 25 MB
4. **BR-GRADE-01 (Grading Integrity):**  
   คะแนนต้องเป็นตัวเลขจำนวนจริง (ทศนิยมไม่เกิน 2 ตำแหน่ง) และต้องอยู่ในช่วง `0 <= คะแนน <= คะแนนเต็ม`
5. **BR-PRIV-01 (Data Isolation):**  
   ข้อมูลการส่งงาน คะแนน และข้อความ Feedback ถือเป็นข้อมูลส่วนบุคคล (PII/FERPA/PDPA) นักเรียนในห้องเดียวกันจะต้องไม่มีสิทธิ์มองเห็นคะแนนหรือไฟล์ของเพื่อน

### 7. ความเสี่ยง คำถามเปิด และข้อจำกัด (Risks, Assumptions & Open Questions)

#### 7.1 ความเสี่ยง (Risks) และแนวทางแก้ไข (Mitigations)
| ระดับความเสี่ยง | ความเสี่ยงที่อาจเกิดขึ้น (Risk) | ผลกระทบ (Impact) | แนวทางแก้ไขและป้องกัน (Mitigation) |
|---|---|---|---|
| **สูง (High)** | โหลดของ Server พุ่งสูงผิดปกติช่วง 15 นาทีก่อน Deadline (Traffic Spike) | ระบบค้าง นักเรียนส่งงานไม่ทัน เกิดข้อร้องเรียนจำนวนมาก | - ใช้ Cloud Object Storage (เช่น S3/GCS) พร้อม Pre-signed URL ในการอัปโหลดไฟล์โดยตรงจาก Browser ไม่ผ่าน Web App Server<br>- ตั้ง Auto-scaling และคิวกระบวนการเบื้องหลัง (Background Worker Queue) |
| **กลาง (Medium)** | นักเรียนอัปโหลดไฟล์เปล่า ไฟล์เสียหาย หรือแกล้งเปลี่ยนนามสกุลไฟล์เพื่อยื้อเวลาส่ง | ครูเปิดตรวจงานไม่ได้ เสียเวลาติดตาม | ทำ File Validation ตรวจสอบความถูกต้องของ Magic Bytes และแสดงคำเตือนให้นักเรียนกดดู Preview ตรวจสอบงานของตนเองก่อนยืนยันส่ง |
| **กลาง (Medium)** | ค่าใช้จ่ายพื้นที่จัดเก็บไฟล์ (Cloud Storage Cost) เพิ่มขึ้นรวดเร็ว | ค่าใช้จ่ายระบบบานปลายในระยะยาว | กำหนด Retention Policy เช่น บีบอัดไฟล์ภาพอัตโนมัติ และย้ายไฟล์ของเทอมเก่าไปเก็บใน Cold Storage |

#### 7.2 คำถามเปิดที่ต้องยืนยันกับ Stakeholder (Open Questions)
1. **ช่องทางการแจ้งเตือน:** ในระยะแรกต้องการเฉพาะการแจ้งเตือนภายในเว็บ (In-app Notification) หรือต้องการเชื่อมต่อกับ LINE Notify / LINE Official Account / Email ด้วยหรือไม่?
2. **เกณฑ์การให้คะแนนแบบ Rubric:** ในระยะแรกต้องการเพียง "คะแนนรวมตัวเลขเดียว" หรือต้องการ "Rubric หลายมิติ (เช่น ความคิดสร้างสรรค์ 5 คะแนน, ความถูกต้อง 5 คะแนน)"?
3. **การเข้าใช้งาน:** โรงเรียน/สถาบันมีระบบ Google Workspace for Education หรือ Microsoft 365 ที่ต้องการให้ทำ Single Sign-On (SSO) ด้วยหรือไม่?
